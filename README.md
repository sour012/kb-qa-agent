# 知识库问答 Agent（kb-qa-agent）

一套**可以溯源、会拒答**的文档问答系统：把制度、流程、技术文档丢进去，用户用自然语言提问，系统先检索原文再作答，每个结论都标注出处；知识库里没有的内容，它直接说没有，而不是编一个。

## 快速开始

```bash
git clone git@github.com:sour012/kb-qa-agent.git   # HTTPS: https://github.com/sour012/kb-qa-agent.git
cd kb-qa-agent

pip install -r requirements.txt

# 1) 建索引（把 data/corpus 下的文档切分、建 BM25 + 向量双索引）
PYTHONPATH=src python -m kbqa build-index

# 2) 提问
PYTHONPATH=src python -m kbqa ask "北京出差住宿一晚最多能报销多少" --trace

# 3) 多轮对话
PYTHONPATH=src python -m kbqa chat

# 4) 跑评测集，生成 reports/eval.md
PYTHONPATH=src python -m kbqa eval

# 5) 起 HTTP 服务（浏览器打开即用）
PYTHONPATH=src python -m kbqa serve
```

不需要 GPU、不需要下载模型权重、不需要 API Key——默认走抽取式回答，纯 CPU 单机可跑。要接入大模型时设 `llm.enabled: true` 和 `DEEPSEEK_API_KEY` 即可，其余链路不变。

## 系统结构

```
                 ┌──────────── 语料层 ────────────┐
  md / txt ──┐   │ loader → 标题树切分 → 句子打包 │
  docx / pdf ─┴──▶│ （标题层级 + 句子边界 + 重叠） │
                 └───────────────┬───────────────┘
                                 ▼
                    ┌──────── 索引层 ────────┐
                    │ BM25（jieba 词法）      │
                    │ TF-IDF（字符 2~3gram）  │──▶ RRF 融合 ──▶ 启发式重排
                    └────────────────────────┘
                                 ▼
  ┌────────────────────────── Agent 层 ──────────────────────────┐
  │ 意图路由 → 多轮改写 → 检索 →（覆盖率低）查询扩展 → 作答 → 引用自检 │
  │                                          │                    │
  │                          抽取式（默认）/ LLM 生成（可选）        │
  └──────────────────────────┬───────────────────────────────────┘
                             ▼
                 回答 + 逐句引用 + 每步耗时 trace
```

## 关键设计（每条都有代价，不是拍脑袋）

| 决策 | 做法 | 为什么 |
| --- | --- | --- |
| 切分 | 标题层级 → 句子边界 → 句级重叠 | 固定窗口会把「第 3 条」拦腰截断，命中后上下文只剩半条规则 |
| 检索 | BM25 + 字符 n-gram 向量，RRF 融合 | BM25 管精确（条款号、编号），向量管同义；RRF 只看名次，避开了两路分数量纲不一致的归一化问题 |
| 是否作答 | 用**字符 bigram 覆盖率**做绝对判据 | RRF 归一化后第一名恒为 1.0，库中无相关内容时也是 1.0，不能用来判断「该不该答」 |
| 答案取材 | 主块优先，其他块要 ≥90% 分才允许补句 | 拼接「看起来相关」的旁支段落，是答案跑偏的主要来源 |
| 自检 | 逐句做字符 bigram 支持度核对 | 模型会把「15 个工作日」写成「两周」；不依赖第二个模型，确定性强、零成本 |
| 拒答 | 覆盖率 < 阈值直接拒，不做「尽力回答」 | 线上最贵的错误是编答案，不是少答一句 |

## 评测结果

`PYTHONPATH=src python -m kbqa eval`（语料 9 篇 / 27 块，评测集 27 条，含 3 条不可回答题）：

| 指标 | 数值 |
| --- | --- |
| recall@1 / @3 / @5 | 100% / 100% / 100% |
| MRR | 1.000 |
| 引用准确率 | 100% |
| 答案关键词命中（金额/时限是否落到答案里） | 95.8% |
| 拒答准确率 | 100% |
| 平均延迟 / p95 | 14.4 ms / 27.7 ms |

**这些数字要打折看**：语料只有 9 篇、评测集是从文档反推出来的，题目与原文措辞高度重合，所以召回接近上限。真实企业语料（几百上千篇、存在同义改写和版本冲突）上，同一套代码的 recall@5 通常在 70%~85%，阈值也需要重新标定。这里的价值是**流程可复现**：改一处策略，一条命令就能看出四项指标各自升降。

`reports/eval.md` 会列出失败样本与命中的 top5，便于定位是召回问题还是重排问题。

## 换成自己的知识库

```bash
# 1) 把 md/txt/docx/pdf 丢进 data/corpus（支持子目录）
# 2) 重建索引
PYTHONPATH=src python -m kbqa build-index
# 3) 用真实问题补评测集（最重要的一步，见 docs/DESIGN.md「评测集怎么建」）
# 4) 按评测结果调 config.yaml 里的 chunk / retrieval / answer 三段阈值
```

## 已知局限

- **单跳检索**：问题需要跨 3 篇以上文档聚合时（「今年一共批了多少笔报销」），检索无能为力，这类问题应走结构化查询。
- **表格与图片**：pdf/docx 只取文本层，表格会退化成一行行文字，图片里的信息完全丢失。
- **无增量索引**：新增文档要全量重建（27 块 0.3 秒，万级块需改成增量 + 持久化倒排）。
- **抽取式不会归纳**：默认模式只摘原句，跨段落归纳必须开 LLM。
- **阈值依赖语料**：`min_coverage` 在示例语料上标定为 0.14，换语料必须重标定。
